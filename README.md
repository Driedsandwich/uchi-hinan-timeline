# うちの避難タイムライン

家族の文と住所から公的な地図を調べ、雨の日に「いつ・誰が・どこへ・何を持って」避難するかを 1 枚にまとめる Web アプリです。

- 公開デモ：<https://uchi-hinan-timeline.vercel.app>（2026-11-06 時点で実 AI に接続した構成）
- 東京AIハッカソン 2026 のために作りました。
- AI の鍵（API キー）がなくても、手元では見本の応答（mock）で最後まで動きます。動かし方は下の節にあります。
- ライセンス：MIT（[LICENSE](LICENSE)）。`docs/` の凡例画像と `tests/fixtures/` の地図タイル・避難場所データは国土地理院などの公的データの写しで、各提供元の利用条件に従います（MIT の対象外）。

名前の案：**① うちの避難タイムライン（採用） ② 雨のまえの家族会議 ③ うちの逃げどき**

家族の自由な文と住所から、公的な地図をサーバーで調べ、雨の日の「いつ・誰が・どこへ・何を持って」を印刷・共有する日本語Webアプリです。**事前の計画を作るもので、今の危険や避難指示を判定するアプリではありません。自治体の指示が優先です。**

公開デモは冒頭の URL にあります。操作方法・見本のデータ・今回の検証結果は [docs/ONBOARDING.md](docs/ONBOARDING.md) を参照してください。過去の公開手順は [docs/DEPLOY.md](docs/DEPLOY.md) に残しています。

## すぐ動かす

Node.js 22.x（22.12以上）、npmが必要です。

```sh
npm ci
npm run dev
```

表示されたローカルURLを開きます。最初は大きな「見本で試す」がおすすめです。見本は記録済みの公的データと架空の家族を使い、AIや住所検索・地図取得のAPIを呼ばずに最後まで進めます。

1. 住所と家族の様子を入れる（見本あり）。場所と家族の確認にチェックを付けます。
2. この家の危険と避難先を見ます。
3. 「家族の約束の1枚を受け取る」で1枚を表示し、印刷・保存・共有します。「最初に戻る」「自分の入力で試す」から続けられます。

自分の入力で試す場合は、住所検索・公的データ取得にネットワークが必要です。AIの設定がなければ既存の `mock` で家族の文を読みます。AIが有効ならボタンに「AI で読む（数秒かかります）」と表示します。読み取り後の確認画面では、家族・位置・手伝う人・準備時間を直せます。屋内避難の条件は自治体の資料で確かめた場合だけ回答してください。

APIは `/api/timeline` の1本です。Vite開発時はミドルウェア、Vercelではesbuildで束ねた `api/timeline.js` が動きます。`npm run build` で型検査・フロント・関数を一緒に作ります。静的ファイルだけの `vite preview` ではAPIが動かないため開発確認は `npm run dev` を使ってください。

## AIとコードの分担

| 段階 | AIが担当すること | コードが担当すること |
|---|---|---|
| 家族の文 | 呼び名・年代・移動・感覚・夜・薬/機器・連絡役・同居/別居をJSON化。質問は最大3つ | zodの厳密な型・件数・長さ検査。名前、根拠、自由記述の属性が原文にあるか照合。確認画面で利用者が訂正 |
| 住所・地図 | 担当しない | 国土地理院住所検索→利用者が代表点を確認→Web Mercatorのz17画素→公式凡例に完全一致する色だけ分類 |
| 避難の判断 | 担当しない | 公開した決まり表、屋内安全確保の条件、複合災害に対応する指定緊急避難場所の照合、距離・時間の計算 |
| 家族へ伝える文 | コードから渡された候補文のうち読みやすい言い回しを選ぶ | id・順序・全行・数字列・全文一致を検査。場所の交換、否定の反転、時刻の追加も拒否。不一致なら定型文 |
| 印刷・共有 | 担当しない | A4用CSS、gzip+base64urlでURLフラグメントへ保存、読込み時の型・容量・外部URLの検査 |

自由なAI作文で「安全」「18時に到着」と補わせません。文章段階は**制約した言い回しの選択**です。通常は抽出1回＋言い回し1回。抽出のJSON/根拠検査に失敗したら1回だけ再試行し、2回を使い切った場合は言い回しを定型文にします。

**要件の衝突の扱い：**「合計2回以内」と「どちらのAI出力も不正なら必ず1回再試行」は、2回目の出力が不正な場合には同時に満たせません。この実装は合計2回を優先し、文章段階の不正出力は再呼出しせず棄却します。文章段階の再試行は未実装です。mockは外部AIを0回呼び、抽出だけを限定的な規則パーサーに置き換え、文章は定型文を使います。

## 本物のAIに切り替える

デプロイ先のサーバー環境変数に次を設定します。**鍵の値はソースや設定例に書きません。`.env.example` も作っていません。** `VITE_` を付けた変数に鍵を設定しないでください。

| 環境変数 | 内容 |
|---|---|
| `AI_PROVIDER` | `mock`（既定）または `openai`（OpenAI互換） |
| `AI_BASE_URL` | HTTPSの互換APIの基底URL。未指定時 `https://api.openai.com/v1` |
| `AI_MODEL` | 接続先で利用可能なモデル名。本物のAIでは必須 |
| `AI_API_KEY` | 接続先の鍵。本物のAIでは必須 |
| `RATE_LIMIT_SECRET` | 32文字以上の秘密の値。本物のAIでは必須 |
| `RATE_LIMIT_MAX` | 同一署名cookieの1分間のPOST上限。既定15、上限60 |
| `IP_RATE_MAX` | 関数の同じ実体でのIP由来ハッシュの10分間上限。既定120 |

`/chat/completions`、JSON出力モードに対応する互換口を使用します。1回18秒で打ち切り、入力やエラー本文をログに出しません。住所は抽出AIへ渡しません。文章AIへはコードが作った行動表の候補を渡すため、家族の呼び名・必要物・避難先名は送られます。AI事業者側の保存の扱いは契約・設定の確認が必要です。

開発時の環境に本物のモデル/鍵がなかったため、**実モデル評価は未実施**です。HTTP応答を差し替える試験では、抽出成功・JSON失敗・原文にない値・呼出し上限・文章の棄却を検証しています。実モデル性能と同一視しません。

### 住所

[国土地理院住所検索](https://msearch.gsi.go.jp/address-search/AddressSearch) の `?q=` にサーバーから送信。戻る候補は最大8件。番地の途中までしか解決できない場合もあり、初めの候補を家の正確な位置だと断定しません。位置の確認を必須にしています。地図での直接クリック選択は未実装です。代わりに地理院地図へのリンクと緯度・経度の修正欄があります。

### 避難先

[国土地理院 指定緊急避難場所の利用方法](https://www.gsi.go.jp/bousaichiri/hinanbasho-help.html) と[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)を確認。データは**z10のGeoJSON**、地図での表示ズームは11〜18です。

`https://cyberjapandata.gsi.go.jp/xyz/skhb01/10/{x}/{y}.geojson`（洪水）、`skhb02`（土砂）、`skhb03`（高潮）、`skhb05`（津波）。指定緊急避難場所と、避難生活を送る指定避難所は異なります。

該当タイルと周囲8枚を取得し、ポイントの `disaster1/2/3/5` フラグをコードで確認。雨の複数の層に着色がある場合は、必要な災害すべてに対応する場所だけを採用します。重複を除き、Haversineの直線距離で10km以内の上位3件。`remarks` の利用階などの条件を画面・行動表に残します。隣接タイルに取得失敗があれば、取得できた範囲の候補と明示します。経路・開設・受入れ・バリアフリーは確認していません。最短ルートや最も安全な場所の保証ではありません。

津波の着色があれば、津波用の候補を別に取得します。雨の警戒レベル3〜5の表には混ぜません。津波では揺れや警報等で直ちに行動する注意を常に表示します。

## 判定の決まりと時間の前提

根拠：[内閣府 避難情報に関するガイドライン（令和8年3月改定）](https://www.bousai.go.jp/oukyu/hinanjouhou/r3_hinanjouhou_guideline/index.html)、[同スライド版](https://www.bousai.go.jp/oukyu/hinanjouhou/r3_hinanjouhou_guideline/pdf/hinan_guideline_r8_3.pdf) のPDF15〜19ページ付近。実装は `src/core/rules.ts` の `RULE_TABLE` と純粋関数です。

| 条件 | 結果 |
|---|---|
| 土砂の着色（指定予定含む） | 立ち退き避難を計画。屋内安全確保を提案しない |
| 洪水・高潮の着色 | 条件不足なら立ち退き避難。下の条件がすべて確認済みなら屋内安全確保を候補にする |
| 無着色・未知の色・取得不能だけ | 避難不要とは決めない。自治体の地図・指示で確認する計画 |
| レベル3 | 危険な場所で時間を要する人と支援者が避難。別居家族の到着を待たない |
| レベル4 | 危険な場所から全員の避難を完了 |
| レベル5 | 遠い指定避難場所への移動を勧めず、その場で命を守る。ここまで待たない |
| 夜になる前 | 悪天候が予想される日の開設・支援・連絡・道の確認。架空の日没時刻や出発時刻を生成しない |

屋内安全確保は、①家屋倒壊等氾濫想定区域（氾濫流・河岸侵食）の外、②浸水しない居室があり全員移れる、③浸水期間を過ごせる備えがある、という公式の条件に合わせます。加えてこのアプリでは、他の雨の災害のおそれも自治体資料で確認し、部屋の呼び名を記入する必要があります。**家屋倒壊区域・浸水継続時間は未取得であり、利用者が資料で確認した事実として扱います。階数だけで安全判定しません。**

歩行速度の参考：[内閣府「南海トラフ地震臨時情報 防災対応ガイドライン」令和7年8月改訂](https://www.bousai.go.jp/jishin/nankai/pdf/honbun_guideline2.pdf)、参考資料「避難の移動速度の設定」（本文160ページ）。資料にある1.0m/秒・0.5m/秒を参考に、自力歩行の成人は1.0、高齢者・子ども・杖/歩行器は0.5と**仮に当てはめます**。この人の実測値や大雨の中の保証値ではありません。

`ceil(直線距離[m] × 1.5 ÷ 速度[m/秒] ÷ 60) + 準備時間[分]`

道のり1.5倍、準備時間の初期値20分は公的な規定値ではなく、変更可能/明示した仮の前提です。車いす・歩行困難・移動不明・避難先未確定は計算しません。別居家族の迎えの到着も計算しません。60分を超える見積もりでは、広域避難・移送について事前に相談する注意を追加します。

## 試験・評価

```sh
npm test
npm run build
npm run eval
npm run eval:live
npm run eval:ai
npm run verify:ui
```

- `npm test`：凡例画像の各段と色表の独立照合、保存した実タイル、屋内条件の全16組合せ、複合災害の避難先、距離・時間、数字/場所/否定の変更拒否、API失敗、呼出し予算、HTTP境界・回数制限。
- `npm run eval`：合成家族文14件の8項目を人単位で照合。配列順・人の過不足も減点。薬の順序は無視。根拠引用・質問の言い回しは一致率に含めない。mockと本物で同じケース・採点式。
- `npm run eval:live`：同じ14件に加え、3地点の住所代表点と18層の状態・RGBA・区分を再取得照合。公的配信の変更や障害では失敗する設計。記録更新を自動で合格扱いにしない。
- `npm run eval:ai`：環境変数の実モデルを使用。未設定なら終了コード2で「未実施」。mockに黙って切り替えない。
- `npm run verify:ui`：起動済みのViteに接続。既定 `http://127.0.0.1:5174`、`TEST_BASE_URL`で変更可能。Playwright Chromiumが必要（`npx playwright install chromium`）。3見本と同じ住所・家族を自分の入力欄から送信し、新規住所/家族、390px画面の横はみ出し、共有再読込時のAPI不使用、失敗時の入力保持を検査。
- `npx tsx scripts/verify-bundle.ts`：生成された単一APIをNodeで起動し、公的データを使って最初から最後まで検証。

結果JSON：[docs/results](docs/results)。評価台本：[eval/JUDGING.md](eval/JUDGING.md)。mockの既知の失敗も結果に残します（複雑な言い回し・否定の理解は苦手）。mockの97.73%を本物のAIの精度として示しません。

## 保存・共有・制限

住所と家族の文/結果は、アプリのサーバーのDB・ファイル・ログに保存しません。処理中のリクエストメモリだけを使用。公的タイルの利用者別キャッシュもなし。回数制限にはIP由来HMACと個数、作成済みトークンID・期限だけをメモリに保持します。ブラウザのlocalStorageも使いません。

共有はgzip+base64urlを `#plan=` 以下へ入れる方式。フラグメントはHTTPリクエストに含まれず、共有表示時はAPIに接続しません。受信時は圧縮データ30KB相当、展開後100KBまで検査し、型・出典URLも検証します。**暗号化・本人認証・改ざん防止署名ではありません。** リンクを知る人は住所・家族の情報を読めます。再取得していない共有計画と表示します。家族へ渡す前に中身を確認してください。

回数制限は署名cookieと関数内のIPハッシュでの簡易制限です。複数インスタンスを横断する強制上限や課金予算の保証は未実装です。作成トークンは30分有効、同じ関数実体での使い回しを拒否します。分散ストアを導入する場合も家族の内容ではなくID/回数だけを保存する設計にできます。

- 家屋倒壊等氾濫想定区域・浸水継続時間・内水の取得は未実装。上階の部屋の実測高さも自動判定しません。
- 最寄りは直線距離。河川を渡る危険や道路寸断は未確認。機器の電源・階段・障害への配慮は施設の受入れ確認が必要。
- A4縦1ページは3つの見本で実測済み。最大8人で非常に長い持ち物や施設条件を記入した場合、読み落としを避けるため改ページを許容します。全ての最大長入力を必ず1ページに圧縮する処理は未実装。
- 実モデル性能・有料AI事業者側の保持設定は未確認。日本語の限定mockが本物の意味理解を代替するわけではありません。
- 共有は過去の計画を読む仕組み。作成後のデータ更新、自治体の指示が優先されます。

自治体の避難情報・ハザード地図・指定緊急避難場所という既存の仕組みを、家族の身体状況と連絡の分担へつなぐことが狙いです。将来の個別避難計画・地域の支援者への連携は構想であり、この版では実装していません。

## B3 家族の約束 UI（2026-11-06）

画面と印刷を `DESIGN.md` のB3案へ変更しました。結果は家族別カードを中心にし、レベル3/4/5を赤・紫・黒で表示します。名前と主行動は大きいまま、長文は折り返します。共有は「家族へ送る」から内容を確認した後にコピーできます。A4は共有操作を除き、家族・支援者・持ち物・連絡先を印刷します。

`.npmrc` は元の名前に戻してあります。依存の追加はありません。元の判定・計算・API・mock・制限・試験は変更していません。当時の変更は共有確認ダイアログの開閉です。今回の導線変更に伴う検証操作の更新は [docs/ONBOARDING.md](docs/ONBOARDING.md) を参照してください。

見本の架空家族と公的データを区別しています。画像例の数値を入力せず、時間の未計算や支援者未定もそのまま表示します。レベル3の対象外の人は、元の行動行に沿ってレベル4のカードになります。

追加のローカル画面確認（先に `npm run dev -- --port 5174` を起動）：

```sh
TEST_BASE_URL=http://127.0.0.1:5174 npx tsx scripts/capture-design.ts
TEST_BASE_URL=http://127.0.0.1:5174 npx tsx scripts/verify-design.ts
```

出力先は `verification/design/`。`DESIGN_OUTPUT` で変更できます。入力・確認・結果・共有を390/1280pxで撮影し、屋内避難・未取得・長い名前・8人の表示も確認します。この確認スクリプトは公開・デプロイを行いません。3つの標準見本はA4各1ページですが、家族人数や自由文が増える場合は可読性を優先して複数ページに流します。
