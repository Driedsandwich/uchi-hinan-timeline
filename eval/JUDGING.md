# 一次審査用・5分で触る台本

## 0:00 — 起点

URLをスマホ幅でも開く。「鍵なしで体験」は文の読み取りだけが限定mockで、ハザードと避難先は実データであることを確認する。

## 0:30 — 平地の見本

「浸水が想定される平地」→位置確認→母の杖、父の難聴、息子の別居を確認する。近くの支援者を「近所の支援者（事前に相談）」として記入してもよい。確認チェック2つ→作成。

期待：洪水3〜5m未満、高潮5〜10m未満。屋内条件が不明なので立ち退き。雨の候補は洪水・高潮の両方に対応する場所だけ。父の歩行状況が不明なら時間を作らない。遠くの息子の到着時間を勝手に計算しない。

## 1:30 — 土砂の見本

新しく作る→梅林小学校の地点。土石流の警戒区域と洪水5〜10m未満を確認。避難先の条件欄（利用する階など）を読む。土砂の着色があると、屋内安全確保の回答を全てyesにしても立ち退きになる。

## 2:10 — 高台の見本

東京大学本郷地区の代表点。洪水は無着色。他の層の404を「危険なし」にしていないか確認。結論は自治体の地図で確認。ここで安全と断言しないことが判定の仕様。

## 2:40 — その場の新しい入力

任意の住所と家族文を入力。公共の例なら「東京都千代田区九段南一丁目2番1号」と「祖父 91歳 同居 車いす 薬が必要。私 27歳 同居 自力歩行 連絡係。」。入力はケースIDで分岐しない。住所代表点・家族の読み取りを確認してから作成する。

期待：祖父の移動時間を歩行速度から捏造しない。公的データが取れないときは未取得と表示する。意味の複雑な文はmockが誤るため、修正画面で直せることを確認する。

## 3:30 — 家族へ渡す

「家族への文をコピー」で数字・場所が行動表と同じことを確認。「A4で印刷/PDF」で1枚を確認。「共有リンクを作る」→別タブで開く。URLは `#plan=` を含み、ネットワークパネルにAPIリクエストが出ない。家族の情報を含むリンクだという説明を確認する。

## 4:30 — AIとコードの境界

`src/core/hazards.ts`（公式色）、`rules.ts`（決まり/距離/時間）、`wording.ts`（全文/数字照合）、`server/providers.ts`（合計2回予算）を読む。`npm test`、`npm run eval`、ネット接続下で`npm run eval:live`を実行。

本物のAIを試す場合は運用者がサーバーの環境変数を設定して再デプロイする。鍵を審査画面で入力させない。`npm run eval:ai`でも同じ14件を評価でき、未設定なら未実施と終了する。

## 見るべき限界

現在の発令状況・開設や安全な経路を取っていないこと、家屋倒壊/浸水継続時間の条件は利用者確認であること、本物のAI評価が未実施であることを隠さない。合成の家族文と公共施設の地点を使う。実際の家族の個人情報を評価ログに残さない。
